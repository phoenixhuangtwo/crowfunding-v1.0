- 实现关联：`src/settlement-detail.ts`、`src/App.vue`、`tests/settlement-detail.test.ts`

## 一、需求背景与目标

当前项目结算明细将第一列笼统标为“员工/项目”，实际只重复展示项目名称，财务无法从表格直接识别每笔认购人员及其缴款时间。目标是在不改变认购数据的前提下，按真实记录补齐认购人员和缴款时间，便于结算前核对。

## 二、目标用户与使用场景

- 目标用户：财务人员。
- 使用入口：项目管理 → 去结算。
- 典型路径：进入项目结算页 → 核对归属项目信息 → 逐笔查看项目、认购人员、缴款时间、有效认购和收益。

## 三、用户可见方案

1. 将“员工/项目”拆分为“项目”和“认购人员”两个独立字段。
2. 认购人员展示认购记录中的用户编号；匹配到现有员工名称时展示为“用户编号 · 姓名”。
3. 新增“缴款时间”，优先展示实际支付成功时间。
4. 历史记录没有支付成功时间但存在支付截图上传时间时，展示上传时间作为兼容值；两者均无数据时展示“-”。
5. 保留“有效认购”和“收益”字段，不改变金额计算。

## 四、边界与非目标

- 不新增或修改认购、缴款、结算数据。
- 不生成模拟认购人员或模拟缴款时间。
- 不改变结算发起、发票上传、OCR（光学字符识别）和结算状态流程。
- 不新增员工管理、人员搜索或导出功能。

## 五、验收标准

1. Given 结算项目存在认购记录，Then 每行分别展示项目和认购人员。
2. Given 用户编号能匹配现有员工名称，Then 展示“用户编号 · 姓名”；无法匹配时至少展示用户编号。
3. Given 记录存在支付成功时间，Then 缴款时间展示支付成功时间且不被上传时间覆盖。
4. Given 历史记录仅存在支付截图上传时间，Then 缴款时间展示上传时间。
5. Given 两个时间均不存在，Then 缴款时间展示“-”。
6. 原有有效认购和收益金额保持不变，`npm test` 与 `npm run build` 通过。

## 六、方案与取舍

直接复用 `Subscription`（认购记录）中的 `userId`、`paymentSuccessAt` 和 `paymentUploadedAt`，不增加冗余字段。支付成功时间代表已确认到账，优先级高于截图上传时间；上传时间只用于兼容缺少成功时间的历史数据。

## 七、章节变更草案

在 §4.9 项目结算补充：认购明细按行展示项目、认购人员、缴款时间、有效认购和收益；认购人员来自真实用户编号并匹配现有姓名；缴款时间优先取支付成功时间，历史数据可回退到截图上传时间，缺失时显示“-”。

## 八、影响面清单

- 权限点：不涉及，沿用财务结算入口。
- 菜单：不涉及。
- DataScope（数据范围）：不涉及，仍只展示当前结算项目记录。
- 状态口径：不涉及，不新增或修改状态。
- 通知：不涉及。
- 搜索：不涉及。
- 后台任务：不涉及。
- AI 边界：不涉及。
- 多端：当前 Web 页面生效；无独立移动端实现。
