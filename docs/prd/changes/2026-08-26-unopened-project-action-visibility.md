## 一、需求背景与目标

未开放项目还没有进入认购、缴款和结算阶段，但项目管理列表仍显示“支付复核”和“去结算”，容易让管理员误以为该项目已有可处理的资金数据。本次让行操作与项目阶段保持一致。

## 二、目标用户与使用场景

- 目标用户：项目管理员、财务人员和公司超级管理员。
- 使用入口：项目管理列表的行操作区。
- 触发场景：查看状态为“未开放”的项目。

## 三、用户可见方案

1. 未开放项目不显示“支付复核”和“去结算”。
2. 未开放项目仍显示“开放”和“更多”，用于完成当前阶段的管理操作。
3. 项目一旦进入非“未开放”状态，恢复显示“支付复核”和“去结算”，并沿用现有“更多”菜单规则。

## 四、边界与非目标

- 不改变项目状态机、开放条件、支付复核或结算的业务处理。
- 不改变“更多”中终止项目和强制接管的禁用条件。
- 不新增权限、通知、搜索或后台任务。

## 五、验收标准

1. Given 项目状态为“未开放”，Then 行操作区只展示“开放”和“更多”，不展示“支付复核”与“去结算”。
2. Given 项目状态为“未满额”或其他非未开放状态，Then 仍显示“支付复核”与“去结算”。
3. 单元测试、全量回归和生产构建通过。

## 六、方案与取舍

采用按项目状态返回行操作可见性的统一规则，与现有“开放”、“终止”和“强制接管”判定放在同一处，避免页面模板中出现多套不一致条件。

## 七、章节变更草案

修改 §4.5：未开放项目仅展示开放和更多，不显示支付复核与去结算；其他项目状态按现有规则展示资金处理入口。

## 八、影响面清单

- 权限点：不涉及。
- 菜单：仅涉及行操作可见性，不新增导航菜单。
- DataScope（数据范围）：不涉及。
- 状态口径：涉及未开放状态的操作可见性，不改存储值或状态转换。
- 通知：不涉及。
- 搜索：不涉及。
- 后台任务：不涉及。
- AI 边界：不涉及。
- 多端：当前 Web 项目管理页生效；无独立移动端实现。
