- 实现关联：`server/procurement-project.ts`、`server/server.ts`、`src/App.vue`、`tests/procurement-sync.test.ts`

## 一、需求背景与目标

当前项目管理列表能展示项目状态和认购、金额、结算等信息，但没有项目负责人，管理员无法直接判断采购项目的原始责任归属。目标是把采购接口返回的创建人纳入项目数据，并在项目管理列表中展示，减少跨系统查询。

## 二、目标用户与使用场景

- 目标用户：管理员、财务和公司超级管理员。
- 使用入口：项目管理。
- 典型路径：同步采购项目 → 在项目管理列表查看项目及其负责人 → 结合项目状态和金额继续配置规则、复核或结算。
- 未同步到创建人的历史项目显示“-”，不伪造负责人。

## 三、用户可见方案

1. 项目管理列表在“项目”之后新增“项目负责人”字段。
2. 采购系统项目的负责人值直接来源于采购订单接口的 `creator`（创建人）字段。
3. 创建人缺失或项目不是采购同步来源时显示“-”。
4. 再次同步采购数据时，系统可为已有规则或认购的受保护项目补齐负责人，但不覆盖项目名称、状态、金额和认购数据。

## 四、边界与非目标

- 不把 `responsiblePerson`（业务负责人）或 `purchasingName`（采购员）混作创建人。
- 不新增负责人编辑、筛选、搜索、员工目录匹配或通知能力。
- 不因负责人缺失阻止项目同步、规则配置、开放、复核或结算。
- 不覆盖受保护项目的既有业务字段。

## 五、验收标准

1. Given 采购接口记录存在 `creator`，When 映射为内部项目，Then 项目负责人保存为该创建人值。
2. Given 管理员进入项目管理，Then 列表在项目列后显示“项目负责人”。
3. Given 项目负责人缺失，Then 列表显示“-”。
4. Given 已有规则、认购或非未开放状态的采购项目，When 再次同步，Then 只允许补齐负责人，原项目名称、状态、金额和认购数据保持不变。
5. `npm test` 与 `npm run build` 通过。

## 六、方案与取舍

本期严格按用户指定口径使用采购接口的 `creator`，不推断姓名或改用其他责任人字段。为兼容已进入业务流程的采购项目，同步合并允许单独补齐负责人，其余字段仍受原有保护规则约束。

## 七、章节变更草案

在 §4.5 项目管理补充：项目列表展示项目负责人；采购同步项目的负责人来自接口 `creator` 字段，缺失时显示“-”。再次同步可为受保护项目安全补齐负责人，但不得覆盖其项目状态、金额、规则和认购数据。

## 八、影响面清单

- 权限点：不涉及，沿用项目管理查看权限。
- 菜单：不涉及。
- DataScope（数据范围）：不涉及，沿用当前项目列表范围。
- 状态口径：不涉及，不改变项目状态机。
- 通知：不涉及。
- 搜索：不涉及，本期不按负责人搜索。
- 后台任务：不涉及，仍由手动采购同步触发。
- AI 边界：不涉及。
- 多端：当前 Web 项目管理页面生效；无独立移动端实现。

## 九、开放问题

- `creator` 当前按接口原值展示；如后续需要把创建人编号转换为姓名，需接入权威员工目录并另行确认映射规则。
