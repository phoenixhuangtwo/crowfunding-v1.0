- 状态：merged

- 发起人：用户浏览器批注
- 需求落点：增强现有模块
- 涉及章节：01-内部资金认购平台 §4.9 项目结算
- 实现关联：`src/settlement-flow.ts`、`src/App.vue`、`tests/settlement-flow.test.ts`

## 一、需求背景与目标

当前项目结算页在财务尚未发起结算时即展示发票上传入口，页面阶段与实际操作顺序不一致。目标是先由财务确认发起结算，再开放发票上传，使结算流程顺序清晰，并避免财务提前上传。

## 二、目标用户与使用场景

- 目标用户：财务人员。
- 使用入口：项目管理 → 去结算。
- 典型路径：进入结算页 → 核对项目信息与认购明细 → 点击“发起结算” → 在弹窗内确认 → 上传项目发票。
- 取消确认时继续停留在结算核对阶段，发票入口保持隐藏。

## 三、用户可见方案

1. 初次进入项目结算页时不展示“上传发票”区域。
2. 财务点击“发起结算”后看到确认弹窗，弹窗明确说明确认后将进入发票上传阶段。
3. 财务确认后展示“上传发票”区域，并提示结算已发起、请继续上传发票。
4. 财务取消或关闭弹窗后，不展示上传入口，也不显示成功提示。
5. 再次从项目管理进入结算页时恢复初始核对阶段，上传入口默认隐藏。

## 四、边界与非目标

- 本期不新增正式结算后端接口，不持久化结算流程阶段。
- 本期不生成真实打款清单，不发送员工通知，不改变项目状态或结算状态。
- 发票 OCR 仍为当前本地模拟交互，生产环境仍需真实识别与验真。

## 五、验收标准

1. Given 财务初次进入结算页，Then 页面不存在发票上传入口。
2. When 点击“发起结算”并取消，Then 上传入口仍不可见。
3. When 点击“发起结算”并确认，Then 上传入口立即可见。
4. When 确认成功，Then 按钮进入不可重复发起状态，页面提示继续上传发票。
5. When 返回项目管理后重新进入结算页，Then 上传入口再次默认隐藏。

## 六、方案与取舍

本期采用页面内临时阶段控制，满足当前 MVP 的操作顺序要求；不伪造已经完成的后端结算、打款清单或通知结果。后续接入正式结算接口时，再将临时阶段替换为服务端结算状态。

## 七、章节变更草案

在 §4.9 项目结算补充：发票上传入口默认隐藏；财务点击“发起结算”并在确认弹窗中确认后才展示。取消确认不改变页面阶段。当前确认仅进入发票上传阶段，不代表结算完成、打款清单生成或员工已收到通知。

## 八、影响面清单

- 权限点：不涉及，沿用财务结算入口。
- 菜单：不涉及。
- DataScope：不涉及。
- 状态口径：涉及页面临时阶段，不新增持久化业务状态。
- 通知：不涉及，不发送真实通知。
- 搜索：不涉及。
- 后台任务：不涉及。
- AI 边界：不涉及。
- 多端：当前 Web 页面生效；无独立移动端实现。

## 九、开放问题

- 正式结算接口、结算状态持久化、打款清单生成与员工通知留待后续需求确认。
