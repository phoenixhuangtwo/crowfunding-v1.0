# 增量 PRD：采购订单映射为内部认购项目

- 状态：merged
- 日期：2026-08-25（2026-08-25 评审通过并合入）
- 发起人：用户与 Codex 会话
- 需求落点：填补现状缺口（采购系统已能只读拉取分页订单，但尚未完成订单到内部项目的字段映射、去重与增量同步）
- 涉及章节：`01-内部资金认购平台`
- 实现关联：`server/procurement-project.ts`、`server/server.ts`、`tests/procurement-sync.test.ts`、`tests/smoke.mjs`

## 一、需求背景与目标

项目管理页已经可以读取真实采购订单并显示数量摘要，但订单明细没有进入内部项目列表，管理员点击后看不到可继续配置认购规则的项目数据。

本次变更将字段完整、成本有效的采购订单安全映射为内部“未开放”项目。同步后管理员可直接在现有项目管理列表查看这些项目，再按当前流程配置规则和开放认购。

## 二、目标用户与使用场景

- 目标角色：管理员、公司超级管理员。
- 使用入口：项目管理页右上角“同步采购系统（MCP）”。
- 典型路径：确认同步 → 系统拉取订单 → 创建或更新安全状态下的项目 → 刷新项目列表 → 查看新增、更新、跳过数量。
- 异常场景：成本缺失或不大于 0 的订单跳过；已开放、已有规则或已有认购的项目不被覆盖。
- 金额口径：采购 API（应用程序接口）的金额单位为“分”，内部系统金额单位为“元”，同步时统一除以 100。

## 三、用户可见方案

1. 同步成功后，符合条件的采购订单直接出现在项目管理列表。
2. 新同步项目统一为“未开放”，不会因采购系统状态直接进入可认购状态。
3. 页面成功提示包含本次拉取、新增、更新和跳过数量。
4. 重复同步使用采购订单 `id`（编号）生成稳定项目编号，不创建重复项目。
5. 已经进入内部业务流程的项目不被外部数据覆盖。

## 四、边界与非目标

- 本期不映射采购状态到内部项目状态；新项目统一为“未开放”。
- 本期不自动创建认购规则、收款码或开放项目。
- 本期不导入成本为空或不大于 0 的采购订单。
- 本期不新增分页控件，仍同步当前固定第一页 10 条。
- 本期不反向修改采购系统订单。

## 五、验收标准

1. `id` 映射为稳定项目编号 `PRJ-FSY-OFFLINE-{id}`；项目名称优先使用 `projectName`，为空时使用 `sellOrder`。
2. `totalCostPrice`、`totalTransactionPrice`、`totalSellingPrice` 均按“分除以 100”转换为“元”。
3. 成本金额来自 `totalCostPrice`；销售金额优先使用大于 0 的 `totalTransactionPrice`，否则使用 `totalSellingPrice`；利润为销售金额减成本金额。
4. `total`（认购基准金额）与 `remain`（剩余金额）初始化为成本金额；进度、已认购金额、人数和各类公司认购金额初始化为 0。
5. 新项目状态为“未开放”，截止时间为空，来源显示采购系统销售订单号。
6. 成本无效订单被跳过；重复同步不产生重复项目。
7. 只有仍为“未开放”且没有规则、没有认购的已同步项目可以更新；其他项目跳过。
8. 同步完成后页面刷新项目列表，并显示新增、更新、跳过数量。
9. 自动化测试和生产构建通过。

## 六、方案与取舍

采用稳定外部编号进行幂等同步，并将所有新项目置为“未开放”，让真实数据接入与内部资金流程保持隔离。相比直接按采购状态开放认购，该方案需要管理员多一步规则配置，但能避免外部字段误触发资金行为。

无有效成本的订单无法形成认购基准金额，因此本期跳过并计数，不创建金额为 0 的项目。

## 七、章节变更草案

### 《01-内部资金认购平台》4.5 项目管理

- 管理员同步采购订单后，字段完整且成本有效的订单映射为内部“未开放”项目，并显示在项目管理列表。
- 系统按采购订单编号去重；只有未开放且没有规则、没有认购的已同步项目允许刷新字段。
- 同步结果反馈拉取、新增、更新和跳过数量。

### 《01-内部资金认购平台》5.3 核心数据对象

- 采购订单金额以“分”为单位，进入 `Project`（项目）前转换为“元”。
- 外部订单 `id` 映射为稳定项目编号 `PRJ-FSY-OFFLINE-{id}`。
