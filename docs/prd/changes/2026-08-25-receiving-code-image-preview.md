## 一、需求背景与目标

创建收款码时，上传控件当前只显示文件名；创建后的收款码列表和认购规则配置也始终显示默认图形，无法核对实际上传图片。本次让用户在上传、管理和选择规则收款码时持续看到同一张真实图片，降低选错收款码的风险。

## 二、目标用户与使用场景

- 目标角色：维护收款码的财务人员，以及配置认购规则的管理员。
- 使用入口：创建收款码弹窗、项目收款码管理列表、创建或修改认购规则弹窗。
- 典型场景：上传后确认图片是否正确，创建后核对图片，配置规则时确认选中的收款码。

## 三、用户可见方案

- 选择图片后，创建弹窗立即展示缩略图；点击缩略图可查看大图。
- 支持重新选择或移除本次图片。
- 创建成功后，收款码列表展示真实缩略图；没有图片的记录展示默认占位图。
- 认购规则配置选择收款码后展示同一张真实图片；没有图片时展示默认占位图。
- 非图片文件不接受，并给出明确提示。

## 四、边界与非目标

- 图片为可选项，不改变既有收款码必填字段。
- 沿用当前前端运行状态保存方式；页面刷新后，新建收款码及其图片一并清除。
- 本期不增加后端文件上传、对象存储或历史图片迁移。

## 五、验收标准

1. 上传图片后，创建弹窗出现真实缩略图并可打开大图预览。
2. 创建后，列表对应行显示同一张真实图片。
3. 规则配置选择该收款码后显示同一张真实图片。
4. 无图片的既有记录继续显示默认占位图。
5. 非图片文件被拒绝，移除图片后恢复上传占位状态。

## 六、方案与取舍

使用浏览器 `FileReader（文件读取器）` 将本次图片转换为内存中的 Data URL（数据地址），随当前收款码对象在前端运行状态中传递。该方案与当前收款码本地交互边界一致，无需新增后端存储。

## 七、章节变更草案

### 《01-内部资金认购平台》4.7 项目收款码管理

- 图片沿用当前前端运行状态，不提供跨刷新持久化。
