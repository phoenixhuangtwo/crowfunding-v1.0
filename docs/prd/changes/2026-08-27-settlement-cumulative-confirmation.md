# 增量 PRD：结算发票累计确认与部分结算

- 日期：2026-08-27
- 状态：merged（已合入）
- 关联模块：项目结算、发票 OCR（光学字符识别）、项目状态、审计日志

## 1. 背景与目标

原“发起结算”只进入发票上传阶段，OCR 结果没有形成可持久化的结算确认，无法表达一张发票只覆盖部分项目销售收入、后续继续补传发票的业务过程。

本次目标是让财务按发票识别金额逐次确认结算：累计金额不足时标记“部分已结算”并继续开放上传；累计金额等于项目销售收入时标记“已完结”并关闭上传入口。

## 2. 用户与入口

- 使用角色：财务。
- 页面入口：项目管理 → 去结算 → 发起结算并确认。
- 核心操作：上传发票、查看 OCR 关键字段、确认本次结算。

## 3. 用户可见规则

1. 页面展示项目销售收入、累计已确认结算金额、剩余待结算金额。
2. OCR 识别出的本次交易金额大于 0 且不超过剩余待结算金额时，展示“确认结算”按钮。
3. 本次确认后累计金额小于项目销售收入，项目状态更新为“部分已结算”，保留发票上传入口，支持再次上传和确认。
4. 一次或多次确认后累计金额等于项目销售收入，项目状态更新为“已完结”，关闭上传入口，只保留已完成提示和历史查看。
5. 本次识别金额大于剩余待结算金额时禁止确认，并明确提示超出金额。
6. OCR 未识别到有效交易金额时不展示确认按钮。
7. 每次确认均持久化发票摘要并写入审计日志；重复提交同一个幂等键不会重复累计。

## 4. 非目标

- 本次不实现真实发票验真、重复票跨项目识别、退款或超额收款处理。
- 本次不生成员工分账付款指令，不发送结算通知。
- 本地角色切换仍不等同于生产级接口鉴权。

## 5. 验收标准

- 首次确认 10,000 元、项目销售收入 24,530.18 元时，项目为“部分已结算”，累计金额为 10,000 元，剩余金额为 14,530.18 元，上传入口保持可用。
- 后续确认 14,530.18 元时，累计金额为 24,530.18 元，项目为“已完结”，上传入口关闭。
- 后续确认金额大于 14,530.18 元时接口拒绝且项目累计金额不变。
- 相同幂等键重复提交只返回原确认结果，不重复累计。
- 刷新页面后累计金额、结算记录、项目状态和审计日志保持一致。

## 6. 设计取舍

- 后续发票按“剩余待结算金额”校验，而不是只按原始项目销售收入校验，避免累计超额。
- 结算确认由服务端计算并持久化，前端只负责展示和提交，避免仅靠页面状态形成资金口径。
