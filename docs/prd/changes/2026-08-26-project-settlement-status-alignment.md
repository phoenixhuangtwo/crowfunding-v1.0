## 一、需求背景与目标

项目管理原先将“未开放”和“未满额”统一显示为“未到结算”，并将中断项目显示为“退款处理中”。这些名称隐藏了项目当前所处的真实阶段，管理员需要结合其他列才能判断项目尚未开放、仍在认购，还是已经中断。

本次将结算状态展示与项目阶段直接对齐，使管理员仅查看结算状态列即可识别项目所处阶段，并能用相同口径进行筛选。

## 二、目标用户与使用场景

- 目标用户：管理员、财务人员。
- 使用入口：项目管理列表及其结算状态筛选。
- 触发场景：查看项目进展、筛选尚未开放或仍未满额的项目、识别已中断项目。
- 空状态：筛选后没有匹配项目时沿用列表空状态。
- 权限不足：沿用项目管理页面现有可见性与权限控制。

## 三、用户可见方案

结算状态按照项目阶段展示：

| 项目状态 | 结算状态展示 |
|---|---|
| 未开放 | 未开放 |
| 未满额 | 未满额 |
| 已满额、已截止 | 待结算 |
| 已中断 | 已中断 |
| 已完结 | 已结算 |

结算状态筛选同步提供“未开放、未满额、待结算、已中断、已结算”，筛选结果与列表标签保持一致。

## 四、边界与非目标

- 本期仅调整项目管理页的派生结算状态名称与筛选口径。
- 不改变项目自身状态机，不新增服务端存储字段。
- 不自动发起结算、退款、通知或后台任务。
- 不改变“去结算”入口的可用条件。

## 五、验收标准

1. 未开放项目的结算状态显示“未开放”，不再显示“未到结算”。
2. 未满额项目的结算状态显示“未满额”，不再显示“未到结算”。
3. 已中断项目的结算状态显示“已中断”，不再显示“退款处理中”。
4. 已满额或已截止项目显示“待结算”，已完结项目显示“已结算”。
5. 结算状态筛选项与上述五种展示值一致，筛选结果准确。

## 六、方案与取舍

采用项目状态派生结算状态，不增加第二套持久化状态机。这样可以避免项目状态与结算标签产生数据冲突，同时保留“待结算”和“已结算”两个结算阶段语义。

## 七、章节变更草案

项目管理列表的结算状态按项目状态映射：未开放→未开放、未满额→未满额、已满额或已截止→待结算、已中断→已中断、已完结→已结算。筛选项使用同一组展示值。

## 八、影响面清单

- 权限点：不涉及。
- 菜单：不涉及。
- DataScope（数据范围）：不涉及。
- 状态口径：涉及，调整派生结算状态的展示和筛选口径，不改变项目状态机。
- 通知：不涉及。
- 搜索：涉及项目管理页结算状态筛选，不进入全局搜索。
- 后台任务：不涉及。
- AI 边界：不涉及。
- 多端：当前 Web 页面生效；无独立移动端实现。
