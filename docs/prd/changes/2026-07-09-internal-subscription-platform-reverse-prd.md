# 增量 PRD：内部资金认购平台反推基线

- 状态：draft
- 日期：2026-07-09
- 发起人：Codex Agent
- 需求落点：填补现状缺口（仓库已有功能与阶段文档，但缺少 `docs/prd/` AutoDev PRD 基线）
- 涉及章节：`docs/prd/README.md`、`docs/prd/01-内部资金认购平台.md`
- 实现关联：未进入代码实现；本轮只生成产品文档

## 一、需求背景与目标

当前项目已经具备内部资金认购平台的本地 MVP，包括员工认购、认购规则配置、项目开放 / 中断、支付 OCR 模拟、财务复核、项目结算、公司兜底、权限矩阵、审计日志和风险事件。但仓库缺少 AutoDev（自动开发团队）要求的 `docs/prd/` 产品基线，后续若继续生成测试契约、实现变更或合入基线，缺少统一事实源。

本次目标是根据当前项目事实反推出 PRD（Product Requirements Document，产品需求文档）基线，让后续产品评审、测试契约和实现工作都能引用同一份 As-Is（现状）文档。

## 二、目标用户与使用场景

| 目标用户 | 使用场景 | 需要解决的问题 |
|---|---|---|
| 产品经理 | 评审当前 MVP 是否覆盖内部认购核心闭环 | 需要从用户视角理解页面、状态、规则和非目标 |
| 后端研发 | 根据现有 API 和未来生产化差距规划数据库、鉴权、MCP、OCR、支付能力 | 需要明确哪些是当前事实，哪些是生产化缺口 |
| 前端研发 | 维护角色页面、状态展示、表单校验和跳转入口 | 需要统一页面名称、角色名称和用户可见行为 |
| 测试工程师 | 生成测试契约、覆盖矩阵和 E2E（End-to-End，端到端）用例 | 需要稳定的验收标准和状态机 |
| 财务 / 管理层 | 判断支付复核、结算、兜底和强制接管是否符合业务规则 | 需要识别待确认规则和人工终审点 |

## 三、用户可见方案

1. 建立 `docs/prd/README.md` 作为 PRD 基线索引，登记当前产品章节和本次 draft 增量 PRD。
2. 建立 `docs/prd/01-内部资金认购平台.md` 作为当前产品基线，覆盖模块定位、目标用户、核心流程、页面行为、状态口径、API 锚点、边界约束、模块关系和验收标准。
3. 保留 `docs/01-产品PRD.md`、`docs/02-需求规格说明书.md`、`docs/05-测试用例.md` 等既有阶段文档，不覆盖旧产物。
4. 本轮不把增量 PRD 状态改为 `approved`，也不进入业务代码实现。

## 四、边界与非目标

- 本轮不修改 `src/App.vue`、`server/server.ts`、`data/dev-state.json` 或测试代码。
- 本轮不生成新的测试契约目录；若用户确认后按完整 AutoDev 流程继续，应加载 `$prd-test-case-generator` 并生成 `docs/tests/<prd-stem>/`。
- 本轮不接入真实数据库、真实登录、真实 MCP、真实 OCR、真实支付或对象存储。
- 本轮不把当前 PRD 视为生产发布批准，只作为反推基线和后续评审输入。

## 五、验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AC-PRD-001 | PRD 基线索引 | `docs/prd/README.md` 存在，并登记基线章节与本次 draft 变更 |
| AC-PRD-002 | 基线章节 | `docs/prd/01-内部资金认购平台.md` 存在，覆盖当前项目核心角色、页面、流程、状态和验收标准 |
| AC-PRD-003 | 状态合规 | 增量 PRD 状态保持 `draft`，未经用户确认不改为 `approved` |
| AC-PRD-004 | 事实锚点 | PRD 引用当前页面、API、状态值、角色和已存在阶段文档 |
| AC-PRD-005 | 不改业务行为 | 本轮只新增文档，不修改前后端业务代码 |

## 六、方案与取舍

采用“直接建立 As-Is 基线 + draft 增量留痕”的方案，而不是只新增一篇散落 PRD。原因是 AutoDev 后续需要稳定的 `docs/prd/README.md` 和章节化基线，测试契约、自动化矩阵、实现报告和基线合入都应引用该目录。

取舍：本轮没有按完整 AutoDev 流程继续生成测试契约，因为用户明确请求是“反推出 PRD 文档”。若继续落地，需要再进入测试契约阶段并暂停等待确认。

## 七、章节变更草案

- 核心流程。

- API 与实现锚点。

新增 `docs/prd/README.md`，登记章节索引、变更目录和文档规则。

## 八、影响面清单

| 影响项 | 结论 |
|---|---|
| 权限点 | 涉及。PRD 明确员工、管理员、财务、公司超级管理员和系统任务的用户可见职责；生产权限仍需后端 RBAC。 |
| 菜单 | 涉及。PRD 登记项目列表、我的认购、项目管理、认购规则配置、项目收款码管理、支付复核、项目结算、公司兜底管理、权限管理、审计日志。 |
| DataScope（数据范围） | 不涉及新增。当前本地 MVP 未实现部门数据范围；生产化时需单独评估。 |
| 状态口径 | 涉及。PRD 固化项目状态、支付状态、规则锁定和中断返款口径。 |
| 通知 | 部分涉及。当前以页面提示、风险事件和返款提醒为主，未接外部通知。 |
| 搜索 | 不涉及新增。当前只有页面内筛选和关键字搜索，未进入全局搜索。 |
| 后台任务 | 部分涉及。当前只有 MCP 同步模拟和状态归一化，未接真实异步任务。 |
| AI 边界 | 不涉及。当前平台不依赖 AI 自动决策。 |
| 多端 | 部分涉及。当前为 Web 本地管理台，移动端 / 企业工作台待确认。 |
