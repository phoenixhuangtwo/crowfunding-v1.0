# 增量 PRD：结算 OCR 固定展示回单关键字段

- 状态：merged
- 日期：2026-08-26
- 发起人：用户浏览器批注 / Codex 实现
- 需求落点：增强现有模块（将通用 OCR 全文归一化为财务核对字段）
- 涉及章节：01-内部资金认购平台 §4.9、§6、§9、§10
- 实现关联：`server/invoice-ocr.ts`、`tests/invoice-ocr.test.ts`、`tests/smoke.mjs`

## 一、需求背景与目标

高精版 OCR 返回的是整段通用文字，财务需要在大量回单文本中自行寻找交易信息，核对效率低且容易看错金额。本次将识别结果固定整理为交易日期、付款人、收款人、交易金额四项，帮助财务快速核对关键资金信息。

## 二、目标用户与使用场景

- 目标用户：负责项目结算的财务人员。
- 入口：项目管理 → 去结算 → 上传图片并完成 OCR。
- 主流程：识别成功后，在实际图片旁固定展示四项关键字段。
- 不完整识别：某项无法可靠提取时仍保留该字段位置，并显示“未识别”，财务可对照原图处理。

## 三、用户可见方案

1. 识别结果固定按交易日期、付款人、收款人、交易金额顺序展示。
2. 交易金额统一以 `CNY 10,000.00` 格式展示，支持识别中文或英文括号、人民币符号、CNY 标识及千分位空格。
3. 任一字段无法提取时显示“未识别”，不使用项目金额、其他票面数字或模拟数据补齐。
4. 实际上传图片继续保留并支持放大，财务对结构化结果保留人工核对权。

## 四、边界与非目标

- 本期只提取四项关键回单字段，不展示完整 OCR 原文，也不自动判断付款人与项目主体是否一致。
- 不新增验真、重复回单检测、自动结算或付款账户校验。
- OCR 结果不直接修改项目、认购或结算状态。

## 五、验收标准

1. 完整回单识别后固定显示交易日期、付款人、收款人、交易金额四项，不再展示整段“识别全文”。
2. `CNY10, 000.00`、`￥520.00` 等格式能分别归一化为 `CNY 10,000.00`、`CNY 520.00`。
3. 付款人或收款人缺失时，对应字段显示“未识别”，其余字段仍正常展示。
4. 页面金额数值与结构化“交易金额”来自同一次 OCR 结果，不使用项目销售金额代替。
5. 全量单元测试、OCR 代理冒烟测试和生产构建通过。

## 六、方案与取舍

在服务端 OCR 适配层完成字段提取，前端继续消费统一字段数组，不增加供应商格式耦合。金额只在明确的“小写金额”“交易金额”或“价税合计”标签附近提取，避免误取账号、业务编号或大写金额中的数字。

## 七、章节变更草案

修改 §4.9：OCR 成功后固定展示交易日期、付款人、收款人和交易金额；缺失项展示“未识别”；交易金额统一格式化，并保留实际图片用于人工复核。同步调整 §6 与 §9 的接口返回说明和验收口径。

## 八、影响面清单

- 权限点：不涉及。
- 菜单：不涉及。
- DataScope（数据范围）：不涉及。
- 状态口径：不涉及项目或结算业务状态。
- 通知：不涉及。
- 搜索：不涉及。
- 后台任务：不涉及。
- AI 边界：OCR 只提供结构化识别建议，财务保留最终核对权。
- 多端：当前 Web 页面生效；无独立移动端实现。

## 九、开放问题

- 不同银行回单的字段标签和排版差异仍需使用更多真实样本持续补充。
- 付款账号、收款账号、业务编号等扩展字段是否需要展示，待后续确认。
