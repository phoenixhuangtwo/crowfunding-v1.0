# 增量 PRD：表格行操作按钮分级收纳

- 状态：merged
- 日期：2026-08-26
- 发起人：用户浏览器批注并确认
- 需求落点：增强现有模块
- 涉及章节：01-内部资金认购平台 §4.5 项目管理、§4.6 认购规则配置、§4.7 项目收款码管理
- 实现关联：`src/admin-project-actions.ts`、`src/App.vue`、`src/styles.css`、`tests/admin-project-actions.test.ts`

## 一、需求背景与目标

项目管理表格原先同时展示支付复核、去结算、开放、终止和强制接管 5 个按钮，操作列过宽且高频与危险操作没有层级，影响列表阅读并增加误触风险。目标是建立清晰的行操作层级，并检查其他页面是否存在同类问题。

## 二、目标用户与使用场景

- 目标用户：管理员、财务和公司超级管理员。
- 使用入口：项目管理及其他带行操作的管理列表。
- 典型路径：浏览项目数据 → 直接执行高频操作，或从“更多”菜单执行低频、危险操作。
- 禁用操作保留原条件，不因收纳而变为可执行。

## 三、用户可见方案

1. 项目管理每行常驻“支付复核”“去结算”。
2. “开放”只在未开放项目显示，使每行常驻业务按钮不超过 3 个。
3. “终止项目”和“强制接管”收进“更多”下拉菜单，并使用危险色提示。
4. “更多”菜单中的禁用条件与原按钮完全一致。
5. 操作列保持右侧固定并缩窄，横向滚动时仍可见。
6. 审计其他表格后，认购规则配置每行最多 3 个按钮，其余列表最多 2 个，不额外折叠。

## 四、边界与非目标

- 不改变任何按钮的权限、业务处理函数、确认弹窗、状态条件和接口行为。
- 不把 3 个及以下操作强制收纳，避免增加高频操作的点击层级。
- 不调整页面导航、筛选、分页或表格字段。

## 五、验收标准

1. Given 任意项目行，Then 常驻按钮不超过 3 个。
2. Given 未开放项目，Then 常驻显示“开放”；其他状态不显示该按钮。
3. Given 项目行，Then “终止项目”和“强制接管”位于“更多”菜单。
4. Given 已满额、已截止等不可终止或接管状态，Then 对应菜单项保持禁用。
5. Given 未满额且剩余金额大于 0，Then “强制接管”菜单项可用。
6. 其他页面不存在超过 3 个同时可见的表格行操作按钮。
7. `npm test` 与 `npm run build` 通过。

## 六、方案与取舍

采用按频率和风险分级，而不是机械保留前三个按钮。支付复核、去结算属于高频导航操作；开放是明确的当前状态动作；终止和强制接管低频且影响资金责任，收纳后仍保留危险色和原确认流程。

## 七、章节变更草案

在 §4.5 项目管理补充：每行常驻支付复核、去结算，未开放项目额外显示开放；终止项目与强制接管收纳到“更多”菜单，保留原状态限制、危险提示和确认流程。管理列表每行操作超过 3 个时按高频常驻、低频或危险操作收纳的原则调整；3 个及以下不强制折叠。

## 八、影响面清单

- 权限点：不涉及，沿用原按钮权限。
- 菜单：涉及行内“更多”菜单，不新增导航菜单或菜单 key。
- DataScope（数据范围）：不涉及。
- 状态口径：不涉及，沿用原项目状态和禁用条件。
- 通知：不涉及。
- 搜索：不涉及。
- 后台任务：不涉及。
- AI 边界：不涉及。
- 多端：当前 Web 管理列表生效；无独立移动端实现。

## 九、开放问题

- 无。后续如单行操作继续增加，应沿用相同的频率和风险分级规则。
