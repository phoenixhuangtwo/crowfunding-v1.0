## 一、需求背景与目标

财务从项目管理进入某个项目的支付复核时，当前待复核队列混合展示了其他项目的缴款记录，容易将凭证、金额和项目对应错误。调整后，财务能够在明确的目标项目范围内逐笔处理全部待复核缴款数据。

## 二、目标用户与使用场景

- 目标用户：财务人员。
- 使用入口：项目管理列表中的“支付复核”。
- 触发场景：财务需要核对目标项目员工上传的缴款截图、OCR（光学字符识别）结果与应付金额。
- 前置条件：目标项目存在支付状态为 `待复核` 的认购记录。
- 空状态：目标项目没有待复核数据时，显示该项目暂无待复核记录，不回退展示其他项目。

## 三、用户可见方案

1. 页面标题区显示当前目标项目名称和编号。
2. 左侧队列只展示目标项目下全部 `待复核` 缴款记录，包括支付单号、员工和金额。
3. 兼容以项目编号或历史项目名称关联的认购记录。
4. 完成一笔复核后，自动选择该目标项目内下一笔待复核记录；没有下一笔时显示空状态。
5. 右侧详情始终对应左侧当前选中的同项目记录。

## 四、边界与非目标

- 不展示其他项目记录，不提供跨项目自动回退。
- 不改变支付复核状态机、按钮权限、OCR 金额或审计规则。
- 不新增菜单、通知、后台任务、搜索或 AI（人工智能）决策。

## 五、验收标准

- 给定两个项目均有待复核记录，从项目 A 进入时队列只显示项目 A 的全部待复核记录。
- 历史记录仅有项目名称但名称与目标项目一致时，仍计入目标项目队列。
- 项目 A 没有待复核记录时显示项目 A 的空状态，不显示项目 B 数据。
- 处理当前记录后，下一条仍属于项目 A。

## 六、方案与取舍

采用项目上下文强约束复核队列，牺牲单页查看全平台待复核记录的便利，换取项目与缴款凭证不串单。全平台队列如有需要应另设明确入口，不在本次复核页隐式混用。

## 七、章节变更草案

- 4.5：从项目管理进入支付复核时携带目标项目上下文。
- 4.8：复核页展示目标项目名称和编号，队列仅包含该项目全部 `待复核` 缴款记录；处理完成后仍在同项目范围选择下一笔。

## 八、影响面清单

- 权限点：不涉及，沿用财务复核权限。
- 菜单：不涉及。
- DataScope（数据范围）：涉及，以当前目标项目作为页面数据范围。
- 状态口径：不涉及，仍只处理 `待复核`。
- 通知、搜索、后台任务、AI 边界：不涉及。
- 多端：涉及当前 Web 页面；暂无独立移动端。
