## 一、需求背景与目标

员工进入“支付收款码与 OCR”页面时，当前面板只显示固定主体和占位图，无法确认当前认购对应的真实收款信息。目标是根据当前认购所属项目及其已启用规则，展示规则实际绑定的收款码，降低误付风险。

## 二、目标用户与使用场景

- 目标用户：需要线下转账并上传支付截图的员工。
- 使用入口：我的认购中的“去支付”“查看支付”或“重新上传截图”。
- 触发时机：员工确认当前认购金额后进入支付页面。
- 正常场景：当前认购可关联到项目、项目规则及启用的收款码。
- 空状态：项目没有可用规则、规则没有绑定收款码、收款码已禁用或图片为空。

## 三、用户可见方案

- 支付页按照“当前认购记录 → 所属项目 → 项目规则 → 规则绑定收款码”匹配数据。
- 匹配成功后展示实际收款码图片、收款主体、收款码名称、账户说明和收款码编号；图片支持点击放大。
- 收款码没有图片时保留默认占位图，同时继续展示其余具体字段和无图提示。
- 未找到可用收款码时显示明确空状态，不回退到其他项目的收款码。

## 四、边界与非目标

- 本期不改变收款码图片仅存在于当前前端运行状态的边界。
- 不改变支付上传、OCR 识别、支付复核和支付状态机。
- 不新增支付接口、文件存储、通知、搜索或后台任务。

## 五、验收标准

1. 从认购记录进入支付页时，只展示该认购所属项目规则绑定的启用收款码。
2. 有图片时展示真实图片并可点击放大，同时显示主体、名称、账户说明和编号。
3. 收款码无图片时显示默认占位图和具体文本字段。
4. 未绑定规则、未绑定收款码或收款码已禁用时显示不可用提示，不展示其他项目数据。
5. 原支付截图上传与 OCR 模拟流程保持可用。

## 六、方案与取舍

采用项目规则精确匹配，不以“第一条启用收款码”兜底。这样可以避免跨项目误付；代价是配置缺失时员工会看到空状态，需要管理员或财务先修正规则。

## 七、章节变更草案

- 4.7：规则绑定的启用收款码可在员工支付页展示图片和具体字段，无图时展示占位图。
