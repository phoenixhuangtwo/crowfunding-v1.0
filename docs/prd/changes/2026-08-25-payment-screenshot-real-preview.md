## 一、需求背景与目标

员工支付页和财务复核页当前用系统生成的“支付成功”卡片代替用户实际上传的支付截图，无法证明财务看到的是员工提交的原始凭证。目标是保存员工实际选择的图片，并让员工和财务在对应认购记录中查看同一张图片，避免模拟内容被误认为真实凭证。

## 二、目标用户与使用场景

- 员工从“我的认购”进入支付页，选择本地支付截图并触发 OCR（光学字符识别）流程。
- 财务从支付复核队列打开同一认购记录，核对实际截图、OCR 结果和应付金额。
- 页面刷新或角色切换后，已成功上传的图片仍可从本地后端状态恢复。
- 历史记录或失败记录没有实际图片时，页面展示明确空状态，不生成模拟截图。

## 三、用户可见方案

- 员工选择图片后，页面展示该图片的缩略预览，支持点击放大；重新选择会替换上一张。
- 只接受图片文件并限制单张大小，格式或大小不符合要求时不提交 OCR，并给出错误提示。
- OCR 模拟按钮仅改变识别结果，不生成虚假图片。
- 图片与认购编号绑定并保存到当前本地后端状态；刷新后再次进入该认购仍显示相同图片。
- 财务复核页展示所选认购记录对应的实际图片，并支持点击放大；没有图片时显示“暂无已上传图片”。

## 四、边界与非目标

- 本期使用当前本地 JSON 状态保存图片数据，不引入对象存储、病毒扫描、图片压缩、生产级访问签名或 CDN（内容分发网络）。
- 不改变 OCR 识别结果、支付复核状态机、菜单和角色权限。
- 不为历史模拟记录补造图片。

## 五、验收标准

1. 员工上传合法图片后看到实际图片预览，原模拟“支付成功”卡片不再出现。
2. 刷新页面并重新进入同一认购记录后仍能查看相同图片。
3. 财务打开该认购的复核详情时看到同一图片，且可点击放大。
4. 历史记录没有图片时，员工和财务页面均显示空状态，不显示模拟截图。
5. 非图片文件或超限图片被拒绝，既不覆盖旧图片也不触发 OCR。
6. “模拟识别通过 / 金额不匹配 / 识别失败”只驱动 OCR 结果，不伪造上传图片。

## 六、方案与取舍

采用与认购记录绑定的数据 URL 持久化，适合当前本地 MVP（最小可行产品）且能保证刷新后复核一致。该方案会增大本地 JSON 文件，生产化时应迁移到受控文件存储并只在认购记录中保存文件标识。

## 七、章节变更草案

- 4.4：员工支付页显示实际上传图片并支持放大、替换和输入校验；OCR 模拟操作不生成图片。
- 4.8：财务复核页显示认购记录关联的同一实际图片，无图时显示空状态。
- 6：`POST /api/payments/ocr` 同步保存合法的支付截图数据和文件名。
- 7：明确当前为本地 JSON 留存，生产环境仍需真实文件存储与安全治理。
