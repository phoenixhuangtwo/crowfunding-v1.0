# 增量 PRD：已有认购规则项目置灰且不可重复选择

- 发起人：用户 / Codex 会话
- 需求落点：增强现有模块
- 涉及章节：01《内部资金认购平台》4.6 认购规则配置
- 实现关联：`src/App.vue`、`server/server.ts`、`tests/smoke.mjs`

## 一、需求背景与目标

管理员创建认购规则时，所属项目下拉仍可选择已经存在认购规则的项目，容易造成同一项目重复配置多条规则，增加开放项目时的选择歧义和配置风险。本次将“一项目一条认购规则”固化为创建约束，让管理员在选择项目时直接识别不可用项目，并阻止重复保存。

## 二、目标用户与使用场景

- 目标用户：管理员。
- 使用入口：认购规则配置 → 创建认购规则 → 所属项目。
- 触发时机：管理员为尚未配置规则的项目创建第一条认购规则。
- 主流程：下拉中未配置规则的项目正常可选；已有规则的项目保留显示但置灰不可选。
- 编辑场景：打开已有规则时继续显示其当前所属项目，不因置灰逻辑导致内容丢失。
- 异常场景：绕过页面重复提交时，系统明确拒绝且不新增规则。

## 三、用户可见方案

创建规则弹窗的所属项目下拉展示全部项目。已有任意状态认购规则的项目以禁用样式展示且无法选择；未配置规则的项目正常选择。若接口收到已有规则项目的新建请求，返回“该项目已存在认购规则，请直接修改原规则”的明确反馈。

## 四、边界与非目标

- 不自动删除、合并或迁移历史规则。
- 不改变已有规则的查看、编辑、启用、停用和删除规则。
- 不改变项目开放时必须使用本项目已启用规则的前置条件。
- 不增加通知、搜索、后台任务或 AI（人工智能）决策。

## 五、验收标准

1. 创建规则时，已有规则的项目在所属项目下拉中可见、置灰且无法选择。
2. 没有规则的项目保持可选，并可正常创建第一条规则。
3. 编辑已有规则时，其当前项目名称正常显示。
4. 对同一项目连续提交两次创建请求时，第二次返回冲突提示，规则总数不增加。
5. 页面刷新后，置灰状态根据当前规则数据重新计算。

## 六、方案与取舍

保留已配置项目并置灰，比直接从下拉隐藏更便于管理员理解项目不可选的原因。前端禁用用于即时反馈，服务端唯一性校验用于保证数据一致性，两层约束共同生效。

## 七、章节变更草案

在 4.6 认购规则配置中增加：一个项目最多存在一条认购规则；创建规则时，已有规则项目在所属项目下拉中置灰且不可选，服务端拒绝重复创建。

## 八、影响面清单

- 权限点：不涉及，沿用管理员规则配置权限。
- 菜单：不涉及。
- DataScope（数据范围）：不涉及。
- 状态口径：涉及规则是否存在的判定，不新增状态值，任意规则状态均计为已配置。
- 通知：不涉及。
- 搜索：不涉及。
- 后台任务：不涉及。
- AI 边界：不涉及。
- 多端：Web 页面生效；当前无独立移动端规则配置入口。
