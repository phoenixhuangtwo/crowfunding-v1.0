# 增量 PRD：收款码图片持久化与更换

## 1. 变更状态

- 状态：merged（已确认并合入）
- 日期：2026-08-25
- 涉及章节：01《内部资金认购平台》4.4、4.7、6、7

## 2. 背景与问题

当前收款码及其图片只保存在浏览器运行内存中，刷新页面或开发服务热更新后会丢失。认购规则虽然绑定了收款码编号，但员工支付页无法稳定展示该编号对应的真实图片，存在误付和无法支付风险。

## 3. 目标

1. 收款码基本信息和图片写入本地 API（应用程序接口）的 JSON（结构化数据文件）状态。
2. 财务可在收款码列表为已有收款码上传或更换图片，并即时预览。
3. 新建、禁用、上传或更换图片后刷新页面，数据仍然存在。
4. 员工支付页严格展示当前项目认购规则绑定的收款码及其实际图片，不跨项目兜底。

## 4. 用户故事

- 作为财务，我希望为已有收款码补传或更换真实图片，避免重新创建收款码和修改既有规则绑定。
- 作为员工，我希望支付页展示当前项目绑定的真实收款码图片，以确认收款主体并完成支付。
- 作为审计人员，我希望收款码创建、图片更换和禁用均留下可追踪记录。

## 5. 功能要求

1. 收款码列表展示持久化的图片；有图时可点击放大，无图时展示占位状态。
2. 每条启用收款码提供“上传图片”或“更换图片”入口。
3. 图片仅支持 PNG、JPG/JPEG、WebP，单文件不超过 5MB；保存前展示预览。
4. 上传图片只更新目标收款码的图片和修改信息，不改变收款主体、编号或规则绑定。
5. 新建收款码、禁用收款码改为调用后端并持久化。
6. 支付页按 `project -> rule -> receivingCodeId` 查找启用收款码；有图显示真实图片，无图明确阻止误导性占位扫码。
7. 既有但已丢失的历史图片不推测、不生成，由财务重新上传真实文件。

## 6. 接口契约

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/receiving-codes` | 获取收款码列表 |
| POST | `/api/receiving-codes` | 创建并持久化收款码 |
| POST | `/api/receiving-codes/:id/image` | 上传或更换指定收款码图片 |
| POST | `/api/receiving-codes/:id/disable` | 禁用指定收款码并记录理由 |

## 7. 验收标准

- AC-001：为 `RCV-20260701-001` 上传合规图片后，接口返回图片和原始文件名。
- AC-002：重新请求列表及读取 `data/dev-state.json`，图片数据仍存在。
- AC-003：SVG、超过 5MB 或无有效文件名的图片被拒绝，原图片不被覆盖。
- AC-004：前端刷新后列表、规则预览和支付页仍展示同一张实际图片。
- AC-005：禁用和创建收款码在刷新后仍保持，并产生审计日志。
- AC-006：没有实际图片时显示“暂无图片”提示，不生成虚假收款码。

## 8. 非目标与边界

- 本期仍使用本地 JSON 持久化，不替代生产对象存储、数据库、鉴权和防病毒扫描。
- 不恢复已经丢失且本地无原文件的历史图片。
- 不改变既有项目、认购规则和收款码之间的绑定关系。

## 9. 回滚与验证

- 回滚：移除新增接口和前端入口，保留原收款码字段；实施前后的本地状态文件由测试自动备份恢复。
- 自动验证：`npm test`、`npm run build`。
- 浏览器验证：收款码列表能打开上传/更换图片弹窗；上传真实文件后刷新仍可查看；项目支付页显示同一图片。
