# 增量 PRD：结算发票识别记录列表与页面底部布局

- 日期：2026-08-27
- 状态：merged（已合入）
- 实现关联：`src/App.vue`、`src/styles.css`、`server/project-settlement.ts`、`server/server.ts`
- 需求落点：增强现有“项目结算”模块

## 1. 背景与目标

项目结算页当前把上传入口与本次 OCR（光学字符识别）结果放在金额汇总和认购明细之前，已确认过的多张发票也没有形成独立、连续可查看的识别记录列表。财务难以先核对项目与缴款明细，再处理结算凭证，也无法快速确认每张图片对应的识别内容和结算结果。

本次目标是调整结算页阅读顺序，并在页面最底部提供可持久化的发票识别记录列表。

## 2. 目标用户与使用场景

- 目标角色：财务。
- 使用入口：项目管理 → 去结算。
- 场景：财务先查看项目金额与认购缴款明细，再上传发票；确认结算后，在页面底部回看所有已确认凭证及逐笔结算结果。

## 3. 用户可见方案

1. 页面顺序调整为：项目信息与金额汇总 → 认购明细与结算操作 → 上传发票 → 发票识别记录。
2. “发票识别记录”固定为项目结算页最底部的业务区块。
3. 每条已确认记录展示：实际上传图片、文件名、交易日期、付款人、收款人、交易金额、确认时间、操作人、结算结果、确认后累计金额和剩余待结算金额。
4. 部分结算记录显示“部分已结算”，足额的最后一笔显示“已完结”。
5. 当前只完成 OCR、尚未点击“确认结算”的图片继续显示在上传区，不进入历史识别记录列表。
6. 刷新页面后，已确认记录及图片仍可查看。
7. 无已确认记录时，底部展示明确空状态。

## 4. 边界与非目标

- 不改变 OCR 接口、识别字段和金额校验口径。
- 不改变部分结算、累计结算、足额完结和幂等规则。
- 不将识别失败或尚未确认的临时图片持久化为已结算记录。
- 当前仍使用本地 JSON（结构化数据文件）持久化图片；生产环境文件存储方案不在本次范围。

## 5. 验收标准

- 认购明细表和“发起结算/等待补充凭证”操作出现在上传发票区之前。
- 上传发票区出现在识别记录区之前，识别记录区为页面最后一个业务区块。
- 确认一张 10,000 元发票后，列表新增一条带实际图片的“部分已结算”记录，并显示确认后累计与剩余金额。
- 后续足额确认时新增“已完结”记录，刷新后两条记录与图片均保留。
- 仅识别但未确认时，底部历史列表数量不增加。

## 6. 方案取舍

- 识别记录以结算确认成功为入列时点，避免把临时 OCR 结果误认为已完成资金动作。
- 本地 MVP（最小可用产品）直接保存受现有 5MB 限制保护的图片 Data URL（数据地址）；生产化仍需迁移到受控文件存储。

## 7. 章节变更草案

- 通知：不涉及。
- 搜索：不涉及。
