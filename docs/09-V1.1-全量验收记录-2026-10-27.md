# V1.1 全量验收记录（2026-10-27）

## 结论与范围

**本次验收不通过，不能签署 V1.1 全量验收。** 依据《20261022-内部员工采购众筹分润系统-SRS需求规格说明书-V1.1》§3.2 的 18 项功能和 §5、§8.3 验收标准逐项核验。验收代码为 `b56233ba`（`cursor/local-mongodb-compose`）；本地 IAM、众筹服务和隔离 MongoDB 可用。下列“隔离通过”指模拟/真实 IAM 搭配随机测试集合的接口验证，不代表真实采购、银行或所有角色的生产流程通过。

本报告以本轮实际运行和代码核查为准。`docs/07-验收报告.md` 及部分旧设计文档仍描述 JSON 存储、旧本地身份或旧测试命令，不能用于 V1.1 签收。

### COS 清理异常

本轮只创建了一个 33 字节、无业务数据的验收对象：

`crowfunding/__acceptance__/550c9df7-e16f-458b-adb6-c93a6c23a239.txt`

对该对象调用当前服务端配置使用的 `TencentCosObjectStorage.deleteObject` 返回 HTTP 403 `AccessDenied`；再次 HEAD 确认对象仍存在。需检查 COS 凭据对该前缀的删除授权，并由有权限者清理此精确对象。验收对象没有写入业务 MongoDB 集合。业务文件替换、解绑、失败补偿也调用相同删除接口，但是否对其实际用途前缀授权须单独验证，当前不能验收完整文件生命周期。

## §3.2 功能逐项判定

状态含义：**隔离通过**＝本轮有隔离自动化证据；**部分通过**＝有实现或局部证据，但完整业务条件未满足；**未通过**＝所需功能未实现或实测失败；**未验证**＝缺外部条件或本轮未执行。全量签收要求无 P0/P1 缺口。

## 验收阻断与复验顺序

1. 实现资金冲正、统一公司复核（含财务本人缴款）、台账查询/导出/完整节点对账，以及已审批分配单的补差闭环；每项用隔离数据和真实公司角色复验。
2. 明确采购作废/取消与 OCR 三字段的外部契约；在真实测试环境验证银行流水、供应商付款/退款和回款差异去向。
3. 修复或明确 COS 测试前缀删除权限，清理上文精确对象；再以业务用途前缀执行上传、读取、替换、解绑和失败补偿验证。
4. 补通知失败重试、每日备份与恢复演练、TLS 和多浏览器/两分辨率测试，按 SRS 指标执行性能与可用性验收。
5. 使用可清理的测试业务单与真实 IAM 员工、项目管理员、财务、公司、审计角色，执行从发布到结单、关闭、采购失败终止的完整浏览器流程；更新旧文档后再签收。
