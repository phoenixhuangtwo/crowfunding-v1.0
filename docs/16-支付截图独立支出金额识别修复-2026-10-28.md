# 众筹1.0支付截图独立支出金额识别修复

仅修改众筹1.0，项目根目录 `/Users/phoenix/Documents/众筹v1.0`。

原因：支付截图中金额独立显示为“-29.90”，OCR服务识别文字成功，但旧提取器仅识别带“交易金额：”等标签的金额。

修改：`server/invoice-ocr.ts` 新增支付凭证类型；保留原标签提取方式，在支付凭证中额外识别带明确负号、两位小数且只有一个候选的支出金额。要求支付成功/付款成功/转账成功标识，排除退款、失败、收款及歧义内容。将支出29.90元作为正金额交给既有缴款复核流程；发票不启用该回退规则。`server/server.ts` 仅在支付截图上传入口传入支付类型。

验证：新增不同负号、退款、失败、收款、多个金额、订单号及发票隔离测试；234项单元测试、原集成回归与构建通过。使用本机同一张“支付成功截图.jpg”向已配置OCR服务真实请求，结果金额29.9，字段显示CNY 29.90；未写入正式业务缴款数据。只记录金额验证结果，未留存OCR全文。后端已重启并健康。

历史已保存失败的识别结果不会自动修改；再次上传图片会执行新规则。原有失败图片仍保留，避免清除复核证据；不要把同一凭证重复上传为多笔支付，最终由财务核对实际交易与应付金额。本次应付1元与截图29.90元不一致，识别成功不等于缴款审核通过。
