# 项目文档规范

## 1. 命名

- 产品文档统一放在 `docs/` 目录。
- 阶段文档使用中文文件名，并保留阶段序号，例如 `02-需求规格说明书.md`。
- 英文缩写首次出现必须补中文说明，例如 SRS（Software Requirements Specification，软件需求规格说明书）。

## 2. 追溯

- 需求统一使用 `REQ-*` 编号。
- 测试用例统一使用 `TC-*` 编号。
- 功能清单、测试用例、验收报告必须能追溯到同一个 `REQ-*`。

## 3. 范围表达

- 必须区分“本地 MVP 已实现”和“生产化待补”。
- 不得把 mock（模拟）数据、前端角色切换、本地 JSON 持久化描述为生产能力。
- 涉及金额时明确使用 RMB/CNY（人民币）语境。

## 4. 质量门禁

- SRS 必须包含 8 个章节。
- 权限矩阵不得留空。
- 测试用例必须覆盖功能、异常、性能、权限四类。
- 验收报告必须逐条对照需求编号给出结论。
