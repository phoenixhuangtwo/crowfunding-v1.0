## 关联一次操作

1. 浏览器开发者工具 Network 中查看接口响应头 `X-Request-Id`。接口失败时页面提示也附带该编号。
2. 在 API 日志中搜索这个编号；每行 JSON 是一个事件。
3. 在审计日志页点击对应记录的「查看差异」，查看真实 before、after 和新记录的请求编号。历史记录没有编号仍可查看；缺失差异显示「未记录」。

事件字段：`http.request` 包含方法、匿名化路由、状态码、耗时和完成/中断结果；`dependency.complete` 包含依赖、操作、耗时和成功/失败；`http.error`、`dependency.error`、`cos.stream.error` 包含异常类型及调用位置。

采购分页、OCR、COS 对象操作和 MongoDB 事务均记录事件。普通数据库查询尚未逐条记录。健康检查请求也会产生访问日志。

日志不记录请求正文、请求头、查询参数、图片、外部响应正文或任意错误消息。异常保留调用位置，避免错误消息携带认证信息。当前没有新增日志轮转；本地启动脚本重新启动时会覆盖日志，排障前应保存所需文件。

## 数据流转

浏览器 → Vite `/api` 代理 → Node API → MongoDB → 查询刷新页面。

- 采购同步：外部采购分页 → 映射项目 → projects → audit_logs。
- 认购：规则校验 → subscriptions + 项目金额/人数 → audit_logs。
- 付款图片：file_assets pending → COS 上传及校验 → ready → OCR → 认购付款状态和审计。
- 结算：上传图片与 OCR 凭证 → 确认结算 → 项目累计金额和审计。
- 图片预览：资产鉴权 → COS 数据流 → 浏览器。

业务集合：projects、subscriptions、subscription_rules、receiving_codes、audit_logs、risk_events、file_assets。实际集合名可能带配置前缀。

## 过期待确认发票的人工清理

识别凭证仅在当前 API 进程内短期有效。页面刷新或服务重启后如遗留未确认发票文件，先运行 `npm run storage:reconcile` 只读盘点，再用 `npm run storage:reconcile -- --asset-id <准确资产ID>` 核对单个资产。确认资产没有被项目结算、付款截图或收款码引用后，才运行 `npm run storage:reconcile -- --apply --asset-id <准确资产ID>`。

清理工具不会批量执行删除。状态为 `ready` 的结算发票还须距创建至少 15 分钟（识别凭证有效期 10 分钟，加 5 分钟缓冲），且创建时间有效；执行前会再次检查业务引用。`pending_delete` 与 `failed` 资产仍按原有单资产规则处理。不要清理报告中仍被引用的资产。
