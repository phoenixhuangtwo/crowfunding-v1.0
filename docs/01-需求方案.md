# 01-需求方案

## 1. 方案摘要

采用“本地 MVP 先闭环、生产能力后替换”的方案：当前项目保留 Vue + Element Plus（前端组件库）实现的多角色工作台，Node.js API 负责业务状态流转和本地 JSON 持久化，先验证内部认购业务流程，再把数据库、认证、MCP、OCR、支付、文件存储替换为生产级服务。

## 2. 核心业务链路

1. 管理员通过 MCP 同步模拟或手工样例项目形成项目池。
2. 管理员为项目配置认购规则和收款码。
3. 管理员开放项目，员工可查看项目详情和剩余可认购金额。
4. 员工确认用户协议、安全协议、风险提示后提交认购。
5. 员工线下转账并上传支付截图，系统执行 OCR 模拟识别。
6. 识别异常或待复核记录进入财务复核，财务可通过、驳回或标记部分缴款。
7. 截止未满额或特殊项目可由公司兜底 / 强制接管。
8. 财务执行项目结算试算，员工确认收款，系统写入审计日志和风险事件。

## 3. 页面与模块方案

| 模块 | 页面 / 能力 | 角色 |
|---|---|---|
| 账号与角色 | 角色切换、账号展示、角色首页 | 员工、管理员、财务、超级管理员 |
| 员工认购 | 项目列表、项目详情、协议确认、创建认购、我的认购、支付 OCR | 员工 |
| 项目管理 | 项目列表、筛选、开放、终止、中断、查看认购、跳转复核 / 结算 | 管理员 |
| 规则配置 | 创建、查看、编辑、启用、停用、删除认购规则 | 管理员 |
| 收款码 | 创建收款码、启用 / 禁用、按项目关联 | 管理员、财务 |
| 财务复核 | 待复核列表、OCR 对照、通过 / 驳回 / 部分缴款 | 财务 |
| 结算 | 项目销售额、成本、利润、公司固定金额、员工认购金额、发票 OCR | 财务 |
| 风险与审计 | 权限矩阵、审计日志、风险事件、公司兜底 | 超级管理员 |

## 4. 状态流转方案

### 项目状态

`未开放` → `未满额` → `已满额` / `已截止` / `已中断` → `已完结`

### 支付状态

`未缴款` → `待复核` → `已缴款` / `部分缴款` / `复核驳回` → `待确认收款` → `已收款`

### 规则状态

`未启用` → `已启用` → `已停用`

## 5. 关键取舍

| 取舍点 | 当前选择 | 原因 | 生产化要求 |
|---|---|---|---|
| 数据存储 | 本地 JSON | 快速验证流程和接口契约 | 替换为数据库事务和迁移脚本 |
| 登录鉴权 | 前端角色切换 | 便于演示多角色流程 | 接入 SSO / OAuth 和后端会话 |
| OCR | API 模拟结果 | 先验证复核闭环 | 接入真实 OCR、置信度阈值、人工复核 |
| 支付 | 线下转账 + 截图 | 匹配当前内部业务假设 | 接入支付流水、回调验签和对账 |
| MCP | 同步模拟 | 验证失败不覆盖、幂等同步思路 | 接入真实 MCP 服务和重试策略 |

## 6. 风险与待确认

- 协议文本是否足以覆盖员工认购风险、亏损承担、收益预期和返款时效。
- 公司固定认购、公司兜底、强制接管的收益归属和审批权限。
- 真实财务对账是否允许“部分缴款”长期存在，还是必须触发补缴 / 退款流程。
- 项目从采购 / 销售系统同步时，哪些字段是权威来源，哪些字段允许本系统覆盖。
- 生产阶段是否以移动端、PC 端或企业工作台作为员工主要入口。

## 7. 收敛结论

本期应以“业务闭环可演示、需求可追溯、测试可执行”为目标，不扩大到真实支付、真实 OCR 和生产权限。后续所有实现与验收以 `docs/02-需求规格说明书.md` 的 `REQ-*` 编号为准。
