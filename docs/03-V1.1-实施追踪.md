# V1.1 实施追踪

## 1. 基线与已确认的口径

- 需求基线：《20261022-内部员工采购众筹分润系统-SRS需求规格说明书-V1.1.md》。SRS（Software Requirements Specification，软件需求规格说明书）第 3.2 节列出 18 项功能，其中 P0 是本期验收必须项。
- 用户确认：使用当前主检出实施，**本轮接入 IAM（统一身份认证系统）**。
- 用户确认：实际分配利润以“已复核客户回款毛额＋已复核公司补款－补款返还－未分配回款差异－采购实付－其他已确认成本”计算；前四项参与分配的金额最多计入发布时应收金额。金额以人民币分为单位；各主体按份额向下取整，尾差归公司。此口径覆盖 V1.1 第 4.8 节“应收－采购”的冲突表述。超额回款须另行登记差异去向，不进入分配。
- V1.1 明确系统只记录线下资金收付，不发起真实转账。发票识别金额不能自动成为客户实收、已分配或已结单的依据。
- IAM 分支旧方案含清空业务库和对象存储的切换步骤；本轮实施以保留现有业务数据与文件为约束。任何清理或迁移须另行设计、核对与授权。

### IAM 合并门禁记录（2026-10-26）

已在临时隔离工作树试合并 `codex/iam-integration`，随后撤销试合并；当前主检出未切换 IAM。合并在后端入口、查询服务、收款码服务、主页面等文件发生冲突。试合并可通过前端构建，但原有 `test:typecheck`（TypeScript 类型检查）文件列表未包含 `server/server.ts`（后端入口）。将入口加入检查后暴露出大量类型错误，且合并路由仍有旧 `requestContext(req)` 角色读取调用。该版本不满足身份防伪和资金接口的切换门禁。

后续须以当前主检出为目标逐接口移植：先纳入完整后端类型检查，再替换旧身份与权限入口，验证业务字段、份额认购和资金复核仍正常；用隔离数据库和模拟 IAM 跑端到端测试，最后用真实 IAM 验证撤权与数据范围。禁止把编译通过或仅前端构建通过当作 IAM 已接入。

## 3. 本期顺序与门禁

按 MoSCoW（必须、应该、可以、本期不做）分档：上述 P0 缺口均为 Must（必须），依据是 V1.1 第 3.2 节优先级和资金控制闭环，不以未经验证的用户量估算 RICE（触达、影响、信心、投入）分数。

| 阶段 | 条目与需求编号 | 通过标准 | 依赖 |
|---|---|---|---|
| 当前 | 修复发票误结单，REQ-V11-INV-001 | 发票确认不改变项目状态；金额非法或重复时不多记；构建和单测通过 | 当前主检出 |
| 下一步 | IAM 登录与逐接口授权，REQ-V11-AUTH-001 | 无令牌拒绝业务请求；每次请求校验身份和操作权限；本人/部门/全部范围正确；失败时不回退本地身份 | IAM 服务、Client 配置、数据归属迁移设计 |
| 下一步 | 回款、采购付款与公司补款，REQ-V11-REC-001 | 逐笔凭证与流水复核；补款经公司复核；可追踪返还与冲抵；金额不可超算 | IAM、资金单据及权限模型 |
| 后续 | 分配和结单，REQ-V11-DIST-001、REQ-V11-LEDGER-001 | 使用已确认利润口径生成分配单；审批、逐人打款、本人确认及分层对账全部完成才可结单 | 已复核回款、采购付款、其他成本与台账 |
| 后续 | 关闭/重开、异常与治理，REQ-V11-CLOSE-001、REQ-V11-GOV-001 | 退款、复核、协议快照、通知和审计按 V1.1 逐项验收 | 前述状态机 |

测试至少覆盖正常、异常、性能、权限四类；在资金审批与结单完成前不得标记 V1.1 已验收。建议业务和财务人工复核利润口径与补款返还的关系，并对历史“已完结”项目逐单核实。

## 4. 客户回款规则模块边界（2026-10-26）

`server/finance/customer-receipts.ts`（客户回款规则模块）以整数分校验拆分流水、凭证识别结果、补款缺口、职责分离和补款返还，`tests/customer-receipts.test.ts`（客户回款规则测试）覆盖相应正常与异常路径。它不访问数据库，也不证明凭证文件已上传、银行流水已核实或资金台账已入账。后续接入 API（应用程序接口）时必须在数据库事务内检查跨业务流水唯一性、凭证资产归属和当前缺口；只有复核成功才能生成只增的资金台账与补款返还记录。IAM（统一身份认证系统）切换完成前，不将该规则模块表述为可供财务正式操作的回款功能。

`server/finance/procurement-payment.ts`（采购付款规则模块）校验付款前的资金闭合、待复核缴款、公司出资确认、银行流水和凭证识别；`tests/procurement-payment.test.ts`（采购付款规则测试）覆盖正常及拒绝路径。该模块同样未连接登记页面与持久化，不能把规则测试通过视为采购付款登记完成。

## 5. 免责协议版本子流程（2026-10-26）

已实现 `server/agreements.ts` 中只增版本和确认记录：公司超级管理员新增版本后立即生效，旧版本只读；无生效版本时认购被拒绝。员工提交认购、查看缴款码和确认收款时分别获取当前版本、滚动阅读后确认；服务端再次检查版本，认购和确认收款与业务更新在同一 MongoDB 事务中保存确认记录。缴款码图片地址不再随员工列表提前下发，查看前须生成确认记录，图片接口只允许最近五分钟内确认过当前版本的员工读取。确认记录列表可按账号、节点和日期查询。测试使用隔离集合，不修改现有业务数据。

当前主检出仍使用模拟身份头；协议管理权限须在 IAM 接入后改为 IAM 授权。确认记录中的姓名目前只能保存本地用户 ID，接入 IAM 后应保存用户姓名快照。浏览器已经展示的缴款码无法在协议版本变化时从用户设备撤回。当前业务库若无生效协议，管理员须先创建经公司审核的协议正文，员工认购才可继续；实施过程不自动生成法律协议或修改历史认购确认。

## 6. IAM 隔离分支进度与切换门禁（2026-10-26）

`codex/v11-auth` 是在当前主检出基础上的隔离工作树，未接管正在运行的 4100/5174 服务。它已接入 OAuth 登录状态、每次业务请求的 IAM 令牌与接口权限校验，并以 IAM 菜单和页面权限显示导航。服务端忽略原本可伪造的本地身份头；IAM 返回的用户标识必须与令牌主体一致。前端不再把演示记录当作加载失败时的业务数据。模拟 IAM 与隔离 MongoDB 集合的接口测试已通过。

当前业务记录尚无租户、用户和部门的 IAM 归属字段。为避免部门管理员直接看到全量历史数据，隔离分支暂拒绝部门范围的业务请求，也拒绝开启多租户模式；这只是切换门禁，不是部门数据范围功能的完成。员工新身份的 IAM 数字 ID 与部分历史记录中的本地账号字符串不同，历史归属必须经可信映射与核对，不能自动按昵称或显示名合并。真实 IAM 服务尚未完成验证，权限码也须在 IAM 侧配置；因此不得切换生产或本地主服务。

后端入口原有的 48 处 TypeScript 类型错误已在隔离分支清理：移除了不参与运行的样例数据初始化，并为实际请求字段补充类型校验。旧版 JSON 内嵌图片请求本来无法生成新版文件资产所需的有效 OCR 凭证，现在明确返回 HTTP 415；当前页面使用的 multipart 文件上传路径保留。`npm run build` 现包含后端入口类型检查。隔离 IAM 接口测试覆盖旧图片格式拒绝、伪造员工账号拒绝、协议版本过期拒绝，并验证有效 IAM 员工认购与协议确认共同落库。测试只使用随机前缀集合，结束后清理。

### 真实 IAM 本地环境核对

IAM 测试 MySQL 旧容器因运行目录残留无效 socket 锁无法启动。保留旧容器和原匿名数据卷，用 `iam-mysql-recovery` 容器挂载同一卷并连接 `docker_default` 网络的 `mysql` 别名后，IAM 后端 `/actuator/health` 返回 `UP`，IAM 前端 5173 返回 200。现有众筹主服务 4100/5174 未切换。

实际 IAM 角色编码是 `crowdfunding_employee`、`crowdfunding_admin`、`crowdfunding_finance`、`crowdfunding_super_admin`，隔离分支已映射。IAM 将页面权限放在 `system_menu`，接口权限放在 `system_api_resource`；原有接口资源包含 `crowdfunding:access`，但缺免责协议管理接口资源和菜单，员工角色缺收款码查询接口授权。`scripts/iam-v11-local-permissions.sql` 已仅在本地 `iam_test` 中以只增、可重复执行方式补齐这三项，二次执行验证无重复记录。直接写数据库不会自动清空 IAM 的 Redis 授权缓存；仅清理众筹相关授权缓存后，新增接口授权在真实 IAM 决策中生效。其他环境须走 IAM 管理流程核准这些权限，不直接运行本地测试脚本。

经用户同意，在 `iam_test` 新建了 `codex_v11_employee` 联调员工账号，随机密码仅保存在本机权限为 600 的 `/Users/phoenix/.config/crowdfunding/iam-v11-test-account.json`。`tests/iam-live.e2e.ts` 使用真实 IAM 完成授权码、PKCE、令牌交换、角色/权限查询，启动隔离众筹 API 后完成协议确认与认购事务，并验证撤销令牌后业务接口返回 401；测试创建的众筹业务集合已清理。另已完成浏览器登录、回调和登出验证，见下文。部门范围管理员写操作仍受门禁限制，不能因员工链路通过就切换主服务。

新开放认购的项目现在会保存 IAM 租户 ID、发布人用户 ID 和部门 ID；隔离集合接口测试确认字段随项目开放一同落库，未开放及历史项目不按姓名推断归属。采购订单再次同步不会覆盖这些归属字段。项目管理员在 IAM 授权其本人或所属部门范围时，项目列表只返回未开放的采购候选项目和本人已发布项目；同部门其他发布人及无归属历史项目均不返回。认购规则只返回本人创建的规则，已发布项目的认购列表只返回本人项目，且不包含员工缴款凭证字段；收款码列表仅供配置查看。项目管理员不能读取全量业务状态、全量审计和风险记录，也不能发起财务结算试算。部门范围管理员页面保留只读项目管理，不显示尚未接通的操作按钮和审计入口。新建规则会记录创建人的 IAM 归属；全范围管理员的规则修改、发布和项目终止仍按发布人归属检查，跨账号及无归属历史记录拒绝。部门范围管理员的写操作仍受门禁限制，历史已发布项目须做可信归属映射后才能管理。

员工查询 `/api/projects` 已在服务端限定为“未满额且认购截止时间尚未经过”的项目；隔离接口测试同时放入未开放和已过期项目，验证员工结果仅包含可认购项目。财务的项目列表仍按现有权限返回。

真实浏览器联调发现登录原先被送往 IAM 后端 `8080/oauth/login`，返回 401；IAM 登录页面实际运行在 5173。已新增 `IAM_WEB_URL`（IAM 浏览器页面地址）并与 `IAM_BASE_URL`（IAM 后端接口地址）分开，`.env.example` 给出本地配置。使用隔离端口和请求定向验证了浏览器跳转到 IAM 5173、凭据登录、回调进入众筹页、登出接口返回 204 并回到 IAM 登录页；原主服务 4100/5174 未被占用或替换，测试集合已清理。联调账号昵称在 `iam_test` 中存有错误 UTF-8 字节，已只修正该账号的昵称并清理该账号的 IAM 授权缓存；刷新后页面显示“V1.1 联调员工”。真实 IAM 授权码与隔离认购接口测试再次通过。

发布接口已要求销售金额高于采购金额、份额规则与采购金额一致、认购截止时间有效。项目发布、IAM 发布人快照、公司前置认购单和审计记录在同一 MongoDB 事务内提交；前置认购单状态为“公司待出资”，不会写入已付款资金台账。公司前置份数为零时不生成零金额认购单。员工个人认购上限可留空，按开放份数作为有效上限。隔离测试验证了正常发布、重复发布无重复公司单，以及公司单编号冲突时整个事务回滚。财务确认公司前置出资及付款前对账仍需接入，不能把“公司待出资”当作已付款。

对本地 `iam_test` 的只读核对显示，`crowdfunding_admin` 角色已获规则创建、更新、启停、删除以及项目开放等接口授权，数据范围限定部门 311；不需再向 IAM 测试库追加这些权限。应用侧仍对该部门范围的写操作保持门禁：目前规则缺 V1.1 要求的缴款截止时间、计划付款日等发布字段，且公司前置出资尚无财务确认闭环。在这些字段和资金约束接入前，不把已通过全范围模拟账号的发布接口作为可正式使用的项目管理员功能。

后续已在隔离分支给按份认购规则补上缴款截止时间和计划付款日：创建、编辑和发布均校验认购截止时间晚于当前时间、缴款截止时间晚于认购截止时间且早于计划付款日，页面表单与项目详情展示这两个日期。新员工认购单的付款期限取提交后 12 小时与项目缴款截止时间中较早者，公司前置认购单记录项目缴款截止时间。隔离 IAM 接口测试覆盖发布后的公司单时间字段及员工认购单期限，独立单元测试覆盖无效日期和边界顺序。此前段落描述的是当时的门禁依据；日期字段已补齐，但公司前置出资仍无财务确认与采购付款前对账闭环，部门范围管理员写操作继续受门禁限制。

自动兜底现按项目缴款截止时间和所有员工认购单的个人付款期限共同判断；仍有待复核或部分缴款记录时等待财务处理，截止后复核驳回的认购与未缴款认购一并释放份额，再生成一次公司兜底承诺单。隔离接口测试先确认待复核期间不生成公司单，模拟复核完成后重启隔离服务，确认释放与公司兜底入库。公司兜底记录仍是待出资承诺，不能计作到账；采购付款登记、凭证核验、出资确认及资金台账尚未接通。

付款前金额核对已增加只读接口 `GET /api/projects/:id/funding-reconciliation`：仅财务或公司超级管理员可读，使用已复核员工缴款台账与公司前置、兜底认购单计算采购金额差额和待复核笔数。员工缴款台账与已缴款认购单不一致时返回冲突，不提供虚假的相符结果；公司金额明确标记为认购承诺，人工到账确认仍为未完成。接口测试覆盖角色拦截、金额差额和孤立台账冲突。该接口不登记采购付款，也不更新公司出资状态。

采购付款登记现已在隔离分支接入：财务通过独立页面选择众筹单、查看付款前对账、上传最多 5 张受控付款凭证，录入金额、银行流水、付款时间、情况说明，并勾选公司出资实际到位。服务器只接受真实上传且归属当前项目和登记人的凭证；当前没有可信采购付款 OCR 结果时，强制走需求允许的“识别失败并说明线下核对”路径，拒绝客户端自报 OCR 成功。登记在 MongoDB 同一事务内重查金额闭合、待复核笔数、缴款截止、流水唯一性和凭证归属，并写入采购付款单、公司出资确认、项目待回款状态、公司及采购付款资金台账和审计；重复登记及失败事务均不留下采购付款记录。付款后员工凭证上传、复核及删除被锁定。新建 `procurement_payments` 和 `bank_transactions` 集合，后者使新增员工缴款复核与采购付款共享唯一银行流水号占用；存量缴款台账也在登记时查重。凭证文件仅财务及公司超级管理员可读，人工清理程序计入采购付款单引用，并为未绑定上传保留 24 小时。

`scripts/iam-v11-local-permissions.sql` 已在本地 `iam_test` 中追加采购付款页面和两项财务接口授权，重复执行验证无重复；仅清理众筹客户端及财务角色的相关 Redis 授权键后，新建的 `codex_v11_finance` 本地联调账号通过真实 IAM 授权码、页面菜单和接口决策验证。随机密码仅存于本机权限为 600 的 `/Users/phoenix/.config/crowdfunding/iam-v11-finance-test-account.json`。其他环境须通过 IAM 管理流程分配权限。采购付款自动 OCR、回款复核、分配与结单仍未实现，不能把当前页面或付款事务表述为 V1.1 整体验收完成。

隔离接口测试补充验证了付款后员工上传凭证被锁定。联调还发现认证层先缓存 multipart（表单文件上传）请求体、上传处理器却再次从已耗尽的流读取，导致上传报错；现由解析器复用认证层已检查的缓冲内容，并把 multipart 总请求上限提高到 12 MB，以支持单张 10 MB 的采购付款凭证。单元测试覆盖预读取后的图片解析。对象存储预检确认本地配置齐全、MongoDB 事务可用，但未把该预检表述为 COS 实际上传成功。

### 客户回款与公司补款接入

隔离分支已增加财务/公司可见的客户回款页面、回款凭证受控上传、拆分流水登记、列表筛选及众筹单回款汇总。登记时在 MongoDB 事务内检查众筹单已完成采购付款、应收金额、公司补款缺口、凭证归属、跨缴款/付款/回款银行流水占用及拆分合计。待复核的公司补款占用可补缺口；客户回款由财务复核，公司补款由不同于登记人的公司角色复核，驳回释放流水号。复核通过才写入只增资金台账，客户回款自动生成补款返还台账，累计达到应收后项目转为待分配。受控凭证只有财务与公司可读，人工清理程序核对回款单引用，并为尚未绑定的凭证保留 24 小时。

当前通用 OCR 只可靠提供部分票据金额，不能可信解析银行流水号及完整到账时间；服务器因此不接受客户端自报识别成功，登记必须注明识别未通过并填写人工核对说明，复核时要求再次录入实际到账金额与银行流水号。**回款凭证自动 OCR 三字段一致性尚未达到 SRS 要求，不能将人工路径表述为自动识别验收。** 银行实际到账由财务线下核验，系统没有银行直连。

`iam_test` 已以幂等脚本配置回款查询、登记、上传、复核权限及客户回款菜单。真实 IAM 财务账号授权码联调确认页面和四项接口授权，模拟 IAM 隔离集合接口测试覆盖补款公司复核、客户回款财务复核、跨业务流水重复、金额不符、权限阻断及自动返还；测试集合结束后清理。主检出 4100/5174 仍未切换到此分支。超额差异去向、分配单审批与打款、退款和结单仍待接入。

超额回款的差异去向现已接入：财务可将超额部分分次登记为“退回客户”或“计入公司”，退款须录入全局唯一银行流水号；每次登记在事务中重查已复核回款超额和未处理余额，同时追加资金台账与审计。回款汇总同时显示超额、已处理和待处理金额，隔离接口测试验证金额超限、跨业务流水复用及角色阻断。该记录为线下退款/去向的系统记账，不发起真实支付。`iam_test` 已追加此项财务接口授权，真实 IAM 财务账号决策验证通过。分配和结单须以待处理差异为零作为门禁。
