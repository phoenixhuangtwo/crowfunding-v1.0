# 00-立项简报

## 1. 项目定位

本项目是内部资金认购平台的本地 MVP（Minimum Viable Product，最小可用产品），用于把线下采购 / 销售项目同步为员工可参与的内部认购项目，并形成项目开放、员工认购、线下缴款、OCR（Optical Character Recognition，光学字符识别）校验、财务复核、公司兜底、结算与审计的闭环。

当前项目路径：`/Users/phoenix/Documents/众筹6-自己的自动开发skill`。

## 2. 问题陈述

当前内部资金认购流程若主要依赖线下沟通、表格登记和人工核验，会产生以下问题：

- 员工无法实时看到项目开放金额、剩余可认购金额、截止时间和本人认购状态。
- 管理员难以统一控制项目开放、认购规则、最低认购金额、收款码和项目中断。
- 财务需要人工匹配支付截图、到账金额、发票和结算结果，容易遗漏异常。
- 公司兜底、强制接管、收益归属、返款承诺和审计追踪缺乏统一台账。

## 3. 目标用户

| 用户角色 | 中文说明 | 核心诉求 |
|---|---|---|
| `employee` | 员工 | 查看项目、确认协议、提交认购、上传支付凭证、查看收益和确认收款 |
| `admin` | 管理员 | 同步项目、配置认购规则、开放 / 中断项目、维护收款码、查看审计 |
| `finance` | 财务 | 复核支付、处理部分缴款 / 驳回、执行结算试算、核对发票 |
| `super_admin` | 公司超级管理员 | 查看权限矩阵、处理公司兜底与强制接管、关注风险事件 |
| `system` | 系统任务 | 执行 MCP（Model Context Protocol，模型上下文协议）同步、状态归一化和审计记录 |

## 4. 成功指标

### 北极星指标

本地 MVP 验收链路覆盖率：员工认购、管理员项目管理、财务复核、公司兜底、审计追踪 5 条核心链路均能在本地前端和 API（Application Programming Interface，应用程序接口）完成可复现操作，覆盖率达到 100%。

### 护栏指标

| 指标 | 目标 | 说明 |
|---|---:|---|
| 防超卖校验 | 认购金额不得超过项目剩余可认购金额 | 当前由单进程 API 校验，生产需数据库事务兜底 |
| 幂等认购 | 同一 `idempotencyKey`（幂等键）只生成一条认购记录 | 已由 `tests/smoke.mjs` 冒烟测试覆盖 |
| 关键动作审计 | 项目、规则、支付、兜底动作均写审计日志 | 当前写入本地 JSON（JavaScript Object Notation，结构化数据文件） |

## 5. 本期范围

- 员工端：项目列表、项目详情、协议确认、认购提交、我的认购、支付截图 OCR 模拟、确认收款。
- 管理端：项目管理、MCP 同步模拟、认购规则配置、收款码管理、项目开放 / 终止 / 中断。
- 财务端：支付复核、部分缴款、驳回、项目结算试算、发票 OCR 模拟。
- 超级管理员端：权限矩阵、审计日志、风险事件、公司兜底与强制接管。
- 技术验证：Vue（前端框架）+ Vite（前端构建工具）+ Node.js（服务端运行时）本地 API、JSON 文件持久化、冒烟测试。

## 6. 非目标

- 本期不接入真实 PostgreSQL（关系型数据库）、MySQL（关系型数据库）或生产数据库。
- 本期不接入真实 SSO（Single Sign-On，单点登录）、OAuth（开放授权）或企业身份系统。
- 本期不接入真实 MCP 服务、真实 OCR 服务、真实支付网关、支付回调验签和对象存储。
- 本期不承诺 500 并发无超卖，需后续压测和数据库事务验证。
- 本期不作为对客发布版本，仅作为内部评审、研发拆解和测试验收基线。

## 7. 约束与依赖

| 类型 | 约束 / 依赖 |
|---|---|
| 技术 | 当前为本地单进程 Node.js API + `data/dev-state.json` 持久化 |
| 数据 | 本地数据为 mock（模拟）和开发验证数据，不代表生产数据 |
| 合规 | 协议文本、亏损承担、本金退回、公司兜底规则需法务或管理层复核 |
| 安全 | 当前角色切换是前端模拟，生产必须后端鉴权和接口级 RBAC（Role-Based Access Control，基于角色的访问控制） |
| 财务 | OCR 自动通过阈值、人工复核责任和付款 / 返款时效需财务确认 |
