## 2. 启动与访问

### 2.1 启动命令

在项目根目录 `/Users/phoenix/Documents/众筹6-自己的自动开发skill` 执行：

```bash
npm install
npm run api
npm run dev -- --host 127.0.0.1 --port 5174
```

命令说明：

| 命令 | 中文说明 |
|---|---|
| `npm install` | 安装前端、API 和测试依赖 |
| `npm run api` | 启动本地 API（Application Programming Interface，应用程序接口）服务 |
| `npm run dev` | 启动 Vite（前端开发服务器）预览页面 |
| `npm test` | 运行 smoke test（冒烟测试） |

API 启动后可访问：

```bash
curl http://127.0.0.1:4100/api/health
```

若返回 `ok: true`，代表本地 API 服务可用。

### 2.3 登录与账号视角

当前 MVP 使用页面内账号视角，不是生产级 SSO（Single Sign-On，单点登录）或 OAuth（开放授权）登录。页面右上角展示当前账号，例如 `employee01 · 当前视角：员工`。生产化时必须替换为后端认证和 RBAC（Role-Based Access Control，基于角色的访问控制）。

| 角色 | 示例账号 | 主要使用场景 |
|---|---|---|
| 员工 | `employee01` | 查看项目、提交认购、上传支付截图、确认收款 |
| 管理员 | `admin01` | 同步项目、配置规则、开放 / 中断项目、维护收款码 |
| 财务 | `finance01` | 支付复核、部分缴款、项目结算、发票 OCR |
| 公司超级管理员 | `superadmin01` | 公司兜底、强制接管、权限管理、审计追踪 |
| 系统 | `system` | 项目同步、状态归一化、系统审计 |

## 4. 全局操作规则

1. 进入系统后先确认右上角账号和当前视角，避免用员工视角执行管理动作。
2. 左侧导航按“员工端”和“项目管理端”分组，员工优先使用“项目列表”“我的认购”，管理和财务使用“项目管理”“认购规则配置”“项目收款码管理”“审计日志”。
3. 金额均以人民币 CNY / RMB 展示，页面使用 `¥` 作为金额符号。
4. OCR（Optical Character Recognition，光学字符识别）在当前 MVP 中为模拟能力，用于演示通过、金额不匹配、识别失败三种状态。
5. MCP（Model Context Protocol，模型上下文协议）同步在当前 MVP 中为模拟同步，不代表已接入真实采购系统。
6. 所有关键动作应写入审计日志，包括认购提交、支付识别、财务复核、规则变更、项目开放 / 中断、强制接管和确认收款。

## 5. 员工端操作

### 5.1 查看项目列表

适用角色：员工。

操作步骤：

1. 打开 `http://127.0.0.1:5174/`。
2. 在左侧点击“项目列表”。
3. 使用“状态”“认购状态”“认购笔数”“项目名称 / 编号关键词”筛选项目。
4. 查看项目状态、认购进度、剩余可认购金额、我的认购状态和截止时间。
5. 点击“查看详情”进入项目详情；仅 `未满额` 项目通常允许“去认购”。

注意事项：

- `未开放` 项目不能认购。
- `已截止`、`已满额`、`已完结` 项目不能继续认购。
- `已中断` 项目需关注返款提示，已缴款金额通常进入返款处理。

### 5.2 项目详情与认购

适用角色：员工。

操作步骤：

1. 在“项目列表”点击目标项目的“查看详情”。
2. 查看项目基础信息、项目来源、开放认购金额、认购时间、收益规则和认购进度。
3. 在“认购操作面板”输入认购金额。
4. 逐项确认“用户协议”“安全协议”“风险提示”。
5. 点击“立即认购”。
6. 提交成功后进入“我的认购”查看认购记录。

校验规则：

- 认购金额不得低于单次认购最低金额。
- 认购金额不得超过剩余可认购金额。
- 必须确认三项协议后才能提交。
- 后端应使用 `idempotencyKey`（幂等键）避免重复提交生成多条认购记录。

### 5.3 我的认购

适用角色：员工。

操作步骤：

1. 点击左侧“我的认购”。
2. 通过认购编号、项目关键词、项目、状态、最低金额和最高金额筛选记录。
3. 查看认购编号、项目名称、申请认购金额、状态、缴款剩余时长、上传时间和预估收益。
4. 对 `未缴款` 记录点击“去支付”。
5. 对 `待确认收款` 记录点击“确认收款”。
6. 对已上传凭证的记录点击“查看支付”查看支付信息。

状态说明：

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| 未缴款 | 已提交认购但尚未上传支付截图 | 去支付 |
| 已缴款 | OCR 通过或财务已确认到账 | 查看支付 |
| 待复核 | OCR 异常，需要财务处理 | 查看支付 |
| 待确认收款 | 项目已结算，等待员工确认收款 | 确认收款 |
| 已收款 | 员工已确认收到款项 | 查看记录 |
| 已释放 | 超时未缴款，认购金额回到项目剩余额度 | 不可支付 |

### 5.4 支付收款码与 OCR

适用角色：员工。

操作步骤：

1. 在“我的认购”点击可支付记录的“去支付”。
2. 在页面左侧查看项目收款码、收款主体和应付金额。
3. 线下扫码支付后，上传支付成功截图。
4. 系统执行 OCR 识别与金额匹配。
5. 当前 MVP 可点击“模拟识别通过”“模拟金额不匹配”“模拟识别失败”验证不同状态。

处理结果：

| OCR 结果 | 系统状态 | 后续动作 |
|---|---|---|
| 识别通过且金额匹配 | 已缴款 | 等待项目结算 |
| 金额不匹配 | 待复核 | 财务进入支付复核 |
| 识别失败 | 待复核或等待重新上传 | 员工重新上传或财务复核 |

## 6. 管理员操作

### 6.1 MCP 同步项目

适用角色：管理员。

操作步骤：

1. 点击“项目管理”。
2. 点击“同步采购系统（MCP）”。
3. 等待提示同步完成。
4. 在项目列表中核对项目编号、项目状态、成本金额、销售金额、利润、截止时间和认购规则状态。
5. 到“审计日志”确认同步动作被记录。

说明：当前 MCP 同步是本地模拟，真实生产环境应接入采购系统，并处理重试、幂等、字段映射和异常告警。

### 6.2 维护项目状态

适用角色：管理员、公司超级管理员。

操作步骤：

1. 在“项目管理”通过项目状态、结算状态或关键词查询目标项目。
2. 查看认购进度、剩余可认购金额、员工未缴款认购金额、公司固定认购金额、剩余可强制接管金额和归属认购利润。
3. 对未开放项目点击“开放”，并选择已启用的认购规则。
4. 对异常项目点击“终止”或“中断”，填写原因并确认。
5. 对需要公司接管的项目点击“强制接管”。

关键限制：

- 开放项目必须有可用规则和收款码。
- 中断必须填写业务原因。
- 中断后页面需提示已缴款金额将在 48h 内原路返款到账。
- 强制接管会影响剩余可认购金额、公司认购金额和利润归属。

### 6.3 认购规则配置

适用角色：管理员。

操作步骤：

1. 点击“认购规则配置”。
2. 点击创建或编辑规则。
3. 选择所属项目和项目收款码。
4. 填写规则名称、开放认购时间、公司固定认购金额、开放参与人数。
5. 确认系统计算的开放认购金额和单次认购最低金额。
6. 配置“是否允许多次认购”“截止后公司兜底”和发布状态。
7. 保存规则。

规则限制：

- 有真实认购记录的规则只能查看，不应修改关键金额、参与人数和收款码。
- 公司固定认购金额必须小于项目成本金额。
- 停用规则后不能用于新项目开放。

### 6.4 项目收款码管理

适用角色：管理员、财务。

操作步骤：

1. 点击“项目收款码管理”。
2. 查看收款码名称、收款主体、账户说明、状态、更新人和更新时间。
3. 新增收款码时上传二维码或录入二维码信息。
4. 启用收款码后，可在规则配置中选择。
5. 禁用收款码时填写禁用原因。

注意事项：

- 禁用收款码不能绑定新规则。
- 生产环境需要保存收款主体资质、二维码文件、操作人和审批信息。

## 7. 财务操作

### 7.1 支付复核

适用角色：财务。

入口：项目管理中的“支付复核”，或支付复核页面。

操作步骤：

1. 进入支付复核页面。
2. 查看认购编号、项目名称、员工、申请认购金额、OCR 识别金额、上传时间和凭证信息。
3. 对金额匹配且已到账记录点击“复核通过”。
4. 对金额不一致记录选择“部分缴款”或“复核驳回”。
5. 驳回或部分缴款时填写原因。
6. 确认复核人、复核时间和审计日志已写入。

处理规则：

- 仅 `待复核` 记录允许复核。
- 复核通过后状态进入 `已缴款`。
- 驳回后员工需重新上传凭证或按线下规则处理。
- 部分缴款需要后续补缴或退款策略，不能直接当作全额到账。

### 7.2 项目结算

适用角色：财务。

入口：项目管理中的“去结算”，或项目结算页面。

操作步骤：

1. 进入目标项目结算页。
2. 核对项目成本金额、销售金额、项目利润、员工实缴金额、公司固定认购金额、公司兜底金额和强制接管金额。
3. 上传或模拟发票 OCR。
4. 查看系统计算的利润分配结果。
5. 确认无误后执行结算。
6. 结算完成后员工端出现“待确认收款”记录。

注意事项：

- 当前 MVP 的发票 OCR 为模拟能力。
- 真实结算必须接入财务凭证、银行流水、发票系统和审批流。
- 结算会影响员工预估收益、待确认收款状态和公司收益归属。

## 8. 公司超级管理员与风险操作

### 8.1 公司兜底与强制接管

适用角色：公司超级管理员。

操作步骤：

1. 在“项目管理”找到截止后未满额或需要介入的项目。
2. 查看“剩余可强制接管金额”和“归属认购利润”。
3. 点击“强制接管”。
4. 核对接管金额、利润归属和对员工认购的影响。
5. 确认后写入审计日志和风险事件。

业务含义：

- 公司固定认购：规则配置时预先设置，公司主动持有的认购部分。
- 公司兜底认购：项目截止后未满额，按规则由公司补足部分或全部剩余额度。
- 公司强制接管：管理层主动接管剩余额度或异常认购额度，收益归公司。

### 8.2 权限管理

适用角色：公司超级管理员、管理员。

操作说明：

1. 生产环境应基于 RBAC 控制员工、管理员、财务和超级管理员权限。
2. 当前 MVP 主要通过前端视角模拟角色，不应作为生产安全边界。
3. 所有敏感 API 必须由后端验证角色，不能只依赖前端按钮显隐。
4. 权限变更需要记录操作人、变更前后权限、变更原因和时间。

### 8.3 审计日志

适用角色：管理员、财务、公司超级管理员。

操作步骤：

1. 点击“审计日志”。
2. 使用关键字、操作类型、项目或时间范围查询记录。
3. 核对操作人、角色、动作、对象、结果和时间。
4. 对资金相关争议，以审计日志、支付凭证和结算记录共同追溯。

重点审计动作：

- MCP 同步项目。
- 新建 / 修改 / 停用认购规则。
- 开放、终止、中断项目。
- 员工提交认购。
- 上传支付截图和 OCR 结果。
- 财务复核通过、驳回、部分缴款。
- 公司兜底或强制接管。
- 项目结算和员工确认收款。

## 9. 常见问题

| 问题 | 可能原因 | 处理方式 |
|---|---|---|
| 页面打不开 | 前端服务未启动或端口不是 5174 | 执行 `npm run dev -- --host 127.0.0.1 --port 5174` |
| API 请求失败 | API 服务未启动 | 执行 `npm run api` 并访问 `/api/health` |
| “去认购”不可用 | 项目不是 `未满额` 或已截止 / 已满额 / 已中断 | 更换可认购项目 |
| “立即认购”不可提交 | 协议未勾选、金额不合法、剩余额度不足 | 勾选三项协议并调整金额 |
| “去支付”后提示已释放 | 认购单超时未缴款 | 重新选择可支付记录或重新认购 |
| OCR 金额不匹配 | 上传截图金额与认购金额不一致 | 进入财务复核或重新上传正确截图 |
| 规则无法编辑 | 规则已被真实认购记录使用 | 只能查看，必要时中断项目并新建规则 |
| 收款码无法选择 | 收款码被禁用或未创建 | 启用收款码或新增收款码 |
| 结算金额不一致 | 成本、销售、实缴、公司接管金额未核对 | 财务先核对项目台账和支付凭证 |

## 10. 本地验证建议

交付或演示前建议执行：

```bash
npm test

```

同时用 Playwright 或浏览器人工确认以下最小链路：

1. 项目列表可打开，能进入项目详情。
2. 项目详情能展示认购金额、协议和“立即认购”入口。

## 11. 生产化边界

当前项目是本地 MVP，不应直接视为生产系统。生产前至少需要补齐：
